# Plan 2 — UI React según el mock aprobado: plan de implementación

> **Para agentes:** SUB-SKILL REQUERIDA: usa superpowers:subagent-driven-development (recomendado) o
> superpowers:executing-plans para ejecutar este plan tarea por tarea. Los pasos usan casillas (`- [ ]`).

**Objetivo:** reemplazar la pantalla de humo por la UI real de tres pantallas (configurar, en curso y resumen)
según `docs/diseno/mock-ui/`, conectada a los bindings y eventos del Plan 1 y lista para grabar en modo demo a 1280×720.

**Arquitectura:** el backend agrega lo que la UI necesita y que hoy no existe: el estado del job consultable
(`GetJobStatus`), que además hace que Wails genere los tipos `Progress`, `Activity`, `Terminal` y `Summary` en
`models.ts`; el desglose del resumen (por subcarpeta y errores separados de omitidos), y la apertura segura de
carpeta y reporte. En el frontend, toda la lógica (formato, fechas, reducer del job, filas del resumen) vive en
módulos puros de `src/lib/` con tests en Vitest. Los componentes de `src/components/` solo pintan y se verifican
visualmente en `wails dev` contra el mock.

**Stack:** Go 1.27, Wails v2.17.1 (`.tools/wails.exe`), React 18, TypeScript 5.6, Vite 5.4, Vitest 2.1,
`@fontsource/inter` y `@fontsource/fira-code`.

**Especificación:** [AGENTS.md](../../../AGENTS.md) (alcance MVP, reglas de Wails y "Referencia visual"),
el mock `docs/diseno/mock-ui/{Main,Progreso,Resumen}.dc.html` (aprobado el 2026-11-12) y
[docs/demo-y-portafolio.md](../../demo-y-portafolio.md) §3 (guion del video). Contrato heredado del Plan 1
([2026-11-12-nucleo-modo-demo.md](2026-11-12-nucleo-modo-demo.md)): la UI guarda el `jobId` vigente y
descarta los eventos terminales de otros jobs.

## Restricciones globales

- Todo texto visible va en `frontend/src/i18n/es.ts`; los componentes no tienen literales en español.
- TypeScript estricto y sin `any` escrito a mano. Los tipos del backend se importan de `../wailsjs/go/models`. No se edita nada en `frontend/wailsjs/`; se regenera con `.tools/wails.exe generate module`.
- Colores solo como variables CSS definidas en `frontend/src/styles/tokens.css`, con los valores de AGENTS.md ("Referencia visual"). Texto y fondos de botón primario en `#0369A1`; texto de estado en `#047857` / `#B45309` / `#DC2626`.
- Estilo: Inter (UI) y Fira Code (consola y rutas); radio de 4 px en controles y 8 px en tarjetas; bordes de 2 px en campos; botones en MAYÚSCULAS con peso 600; títulos de sección de 16 px en primario; carpeta seleccionada con fondo primario sólido; barra de progreso de 24 px con degradado y porcentaje centrado.
- Ventana sin marco (`Frameless: true`) con barra de título propia arrastrable (`--wails-draggable: drag`; los botones, `no-drag`).
- Formato numérico es-ES: miles con punto **también con 4 dígitos** (`1.248`) y decimales con coma (`181,2 MB`).
- Fechas al backend como `YYYY-MM-DD` en hora **local** (nunca `toISOString()`).
- La lógica de `internal/` no importa Wails. Solo `main.go` y `app.go` lo hacen.
- `go test ./...`, `go vet ./...`, `cd frontend && npm test` y `npm run build` pasan al cierre de cada tarea que los toque.
- Cada commit termina con `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Foco de revisión

1. **Evento terminal de un job anterior** que llega después de que empezó uno nuevo (cancelar y relanzar rápido): se ignora y la pantalla de progreso sigue con el job nuevo (Tarea 6, test `ignores terminal of another job`).
2. **Recarga del WebView a mitad de un job** (F5 en `wails dev`): la UI recupera el job con `GetJobStatus` y vuelve a la pantalla de progreso en lugar de ofrecer otro inicio que fallaría con "Ya hay una descarga en curso" (Tarea 2 `TestStatus*` y Tarea 7).
3. **`StartJob` rechazado** (destino inválido o rango invertido): el mensaje en español se muestra en la pantalla de configuración, la UI no cambia de pantalla y la config no se guarda (Tarea 3 `TestStartJobInvalidDoesNotSaveConfig`).
4. **Fechas cerca de la medianoche o de un cambio de mes**: el rango que se envía es el día local elegido, no el día UTC (Tarea 5, test `toIsoDate uses local date`).
5. **Resumen de un job cancelado o con error**: título y estado correctos, contadores parciales y "Abrir reporte" deshabilitado si no hay reporte (Tarea 6 `summaryTitle`, Tarea 3 `TestOpenTargets`).

### Tarea 6: Reducer del job y filas del resumen

**Archivos:**

**Interfaces:**

  ```ts
  export type JobPhase = "connecting" | "scanning" | "downloading" | "reporting"
  export type JobOutcome = "done" | "cancelled" | "error"
  export interface JobState {
    jobId: string | null; request: FormState | null;
    status: "idle" | "running" | "cancelling" | JobOutcome;
    progress: extract.Progress | null;
    phaseEndsMs: Partial<Record<JobPhase, number>>;   // elapsedMs al salir de cada fase
    downloadStartMs: number | null;
    activity: extract.Activity[];                      // máximo ACTIVITY_MAX, la más nueva al final
    terminal: jobs.Terminal | null }
  export const ACTIVITY_MAX = 200
  export type JobAction =
    | { type: "started"; jobId: string; request: FormState }
    | { type: "cancelRequested" }
    | { type: "progress"; progress: extract.Progress }
    | { type: "activity"; items: extract.Activity[] }
    | { type: "terminal"; outcome: JobOutcome; payload: jobs.Terminal }
    | { type: "restored"; status: jobs.Status; request: FormState | null }
    | { type: "reset" }
  export const initialJob: JobState
  export function jobReducer(s: JobState, a: JobAction): JobState
  export function percent(s: JobState): number | null   // solo en downloading: mailsDone/mailsTotal; null = indeterminado
  export function etaMs(s: JobState): number | null      // (elapsed − downloadStart)/mailsDone × restantes; null sin datos
  // summary.ts
  export interface ExtRow { ext: string; count: number; ratio: number }
  export interface ReasonRow { reason: string; kind: "skipped" | "error"; count: number }
  export function extRows(byExt: Record<string, number>): ExtRow[]        // desc por count, luego ext
  export function reasonRows(s: domain.Summary): ReasonRow[]              // desc por count
  export function subfolderRows(bySub: Record<string, number>): { name: string; count: number }[] // asc por nombre
  export function ratePerSecond(s: domain.Summary): number                // saved / segundos(finished − started); 0 si ≤ 0
  export function summaryTitle(outcome: JobOutcome): string               // es.summary.title.{done,cancelled,error}
  ```
